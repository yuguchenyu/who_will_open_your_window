## 1. 背景与问题陈述

### 1.1 背景

主流陌生人社交产品普遍采用"右滑匹配 + 即时聊天"的强节奏交互：用户被鼓励快速、大量地发起接触，聊天被期待即时回复。这类设计对慢节奏、慢热的用户并不友好——开口压力高、回复压力大、被已读不回的挫败感强。同时，现有产品几乎都要求真实注册与多人在线，无法作为一个可独立交付、可离线演示的小型项目实现。

> 按课程要求，本节为背景信息，用于解释需求来源；**实际需求以第 4–6 章为准**，背景不构成需求本身。

### 1.2 问题陈述

如何用轻量的技术手段，验证"以纸条为载体、以七天为周期的慢节奏社交"这一交互设想是否成立？

约束条件决定了本项目的形态：

1. 单人可完成、现有技术条件可实现（纯本地 Web 应用，Node.js 标准库，零第三方依赖）；
2. 没有真实第二用户，"对方"的回应由 AI 模型扮演，且必须**明确标注**为虚拟人物，不冒充真人；
3. 不提供账号体系与公网服务，数据仅存于本机浏览器。

**核心设想的可度量判据**：上述设想是否成立，不以主观判断收尾，而是由第 8 章 **AC-19** 的评审走查与问卷口径检验（场景走通率 + 规则复述正确率 + 开口压力自评对比），使问题陈述与验收标准闭环。

### 1.3 项目定位

本项目是一个**单机、本地优先的交互演示（Demo）**：用户以"递纸条"的方式与 3 位明确标注的 AI 虚拟人物开始交流，以好感记录（心笺）、意愿回顾（回望）和每周期一次的"轻叩窗扉"（双向心意确认）体验慢节奏社交的核心循环。它验证交互与规则设计，不构成可上线的真实交友服务（范围外事项见第 9 章）。

## 2. 目标用户与使用场景

### 2.1 目标用户

| 用户 | 描述 | 核心诉求 |
|---|---|---|
| 主要用户：慢节奏的休闲体验者 | 有耐心、不喜欢即时社交压力的普通用户，以手机使用为主 | 低压力地体验"慢慢认识一个人"的过程 |
| 次要用户：演示/评审观看者 | 想快速了解产品机制的老师或同学 | 在电脑上几分钟内看懂核心流程 |

### 2.2 使用场景（用户故事）

- **S1 递出第一张纸条（手机）**：用户在「遇见」页浏览人物，被某人留的开放话题吸引，写下不超过 100 字的纸条（可借助「拾言」获得三个表达方向的建议），递出后等待回应。递出后不提供已读状态，降低等待焦虑。
- **S2 收到纸条（手机）**：通过演示面板注入一张明确标注的预设来信，用户选择"回复并开始聊天 / 暂存 / 归档"。归档不通知对方。
- **S3 日常聊天（手机/电脑）**：对话中用户随时记录好感分数与私人备注（心笺）；AI 回应失败时消息不丢失，可原样重试且不重复发送。
- **S4 周期性回顾（电脑）**：七天周期结束前，用户在「回望」整理对每个人的意愿（还在了解中 / 想进一步了解 / 有明确好感 / 暂不想继续），并决定是否授权当期揭晓。
- **S5 轻叩窗扉（电脑）**：双方当期均有积极意愿且已授权时，用户确认后得到"有回响 / 暂未确认"的结果；每周期仅一次机会，机会不因对方不可用而消耗。
- **S6 边界操作**：用户可随时屏蔽某人物（立即停止互动、撤销授权），或查看举报说明（解释 Demo 边界并提供屏蔽出口）。

### 2.3 人机界面要求

- 手机优先：390px 为主设计宽度，兼容 320px 窄屏；电脑端 1440px 下为侧栏 + 主区双栏布局。
- 主要可点击控件的有效点击区域至少为 44×44 CSS px（图标视觉尺寸可小于点击区域）；相邻点击区域不得重叠；该尺寸为本次新增验收目标，尚需 AC-21 核验；不可用操作一律置灰并给出原因文案（如"请先完成 AI 配置和连接检查"），不出现点了没反应的情况。

## 3. 运行环境与总体约束

| 编号 | 约束 | 说明 |
|---|---|---|
| C1 | 运行环境 | Windows + Node.js 24；服务仅监听 127.0.0.1 |
| C2 | 零依赖 | 不使用任何 npm 运行时依赖，无需 `npm install` |
| C3 | 数据存储 | 数据仅存于当前浏览器 localStorage；刷新保留，不跨浏览器/设备 |
| C4 | AI 接入 | 仅支持兼容非流式 `POST {base}/chat/completions`、Bearer 鉴权、返回 `choices[0].message.content` 的服务商；接口地址必须是 HTTPS，或 loopback 上的 HTTP |
| C5 | 部署边界 | 无公网部署、无账号体系、无真实多人通信 |
| C6 | 并发边界（新增） | 历史实现只支持单标签编辑；多标签存在最后写入覆盖风险。FR-37 实现后才承诺串行写入，不以 localStorage 单次 setItem 原子性冒充整个动作原子性 |

## 4. 功能需求

优先级定义：**高** = 缺失则核心体验循环不成立；**中** = 显著影响体验完整性与安全边界；**低** = 锦上添花，可后置。优先级与使用频率的对应关系见 4.14。

### 4.1 人物与遇见（页面：遇见）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-01 | 系统提供 3 位 AI 虚拟人物，每位包含姓名、年龄、城市、职业、兴趣、人物设定、回复风格，以及一条对外开放话题（"留一扇窗"）；所有人物页面必须带有"AI 演示人物"标识 | 高 |
| FR-02 | 用户可查看人物完整资料卡 | 中 |
| FR-03 | 用户可编辑自己的演示身份：昵称（≤20 字）、自我介绍习惯（≤100 字）、自己留的开放话题（≤100 字），以及是否接收陌生人纸条的开关（默认开启） | 中 |

### 4.2 递纸条（时间相关）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-04 | 用户可向人物递出纸条，内容必填、去首尾空白、最多 100 字（按 Unicode 字符计数） | 高 |
| FR-05 | **每日额度**：每个本地自然日最多向 2 个**新**人物递纸条，次数不累积到次日；以演示初始时刻所在的时区自然日计算 | 高 |
| FR-06 | **重复限制**：同一人物存在待回应/已暂存/已归档的纸条、或已开始聊天、或已被屏蔽时，不可再递；额度判断在递出前完成并给出明确原因文案 | 高 |
| FR-07 | 递出后纸条状态为"已递出"，**不提供已读状态**；对方回应前该人物处于"待回复"锁定状态 | 中 |

### 4.3 拾言（AI 表达建议）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-08 | 用户写纸条时可选择一个表达方向，调用「拾言」生成恰好 3 条建议；每条含标签（≤12 字）与建议文本（≤100 字），三条方向互不相同 | 高 |
| FR-09 | 点击建议**只填入编辑框**，绝不自动发送；用户可继续编辑 | 高 |
| FR-10 | 拾言必须遵守安全约束：不代替用户发送、不编造用户经历/偏好/情绪/承诺、允许输出"拒绝/换话题/表达边界"类建议；模型返回不符合格式时提示"建议格式不正确，请重新生成"，不展示残缺内容 | 高 |

### 4.4 AI 回应与聊天（时间相关）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-11 | 未完成有效 AI 配置并通过连接检查时，**不开放**投递与聊天，界面给出配置引导；不使用假回复兜底 | 高 |
| FR-12 | 纸条递出后用户可请求 AI 人物回应；回应为非空自然语言文本；送入对话记录的回复硬上限为 3000 字。中文、1–3 句及约 150 字仅是提示词的表达目标，不作为硬性通过条件；回应成功后纸条转为"已接住"并开启正常聊天 | 高 |
| FR-13 | 聊天中用户每发送一条消息（≤500 字）即产生一个待回复任务；同一人物同一时刻最多一个待回复任务，未完成前不可再发 | 高 |
| FR-14 | AI 调用失败（网络/超时/鉴权/限流/格式）时，已发送消息与待回复状态保留；重试**不重复发送**用户消息；不同失败原因给出不同提示文案 | 高 |
| FR-15 | 发送给模型的内容仅限：人物设定、用户主动填写的资料、当前草稿、最近最多 16 条对话（服务端接口上限 20 条）；私人分数、心笺备注、查询记录、授权状态**不得**发送 | 高 |
| FR-16 | 人物回应的提示词包含安全约束：不声称是真人、不输出 HTML、不索要身份证/住址/密码/联系方式、尊重拒绝不施压、不推断隐藏好感分数/查询结果/授权状态 | 中 |

### 4.5 收件流程（Demo 注入）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-17 | 演示面板可将**明确标注为预设演示来信**的纸条注入到指定人物名下（来信标注"预设来信"，不冒充 AI 生成）；该人物已有互动或已被屏蔽时不可注入 | 中 |
| FR-18 | 对收到的纸条可执行：回复并开始聊天 / 暂存（仅自己可见）/ 归档（不通知对方）；已处理的纸条不可重复操作 | 中 |

### 4.6 心笺（私人好感记录）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-19 | 用户可为任一人物记录好感：分数为 0–100 的**整数**，备注最多 200 字；界面提示"具体分数仅自己可见，不发送给 AI" | 高 |
| FR-20 | 心笺数据为纯私人记录：分数与备注不得出现在任何发给模型的内容中，也不得影响对方行为或查询结果 | 高 |

### 4.7 回望与轻叩窗扉（时间相关，核心规则）

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-21 | **七天周期**自浏览器 Demo 初始化时刻起算；用户可查看当前处于第几个周期 | 高 |
| FR-22 | 用户在「回望」为每个人物设定当期意愿（还在了解中 / 想进一步了解 / 有明确好感 / 暂不想继续），并决定是否授权当期揭晓；意愿记录绑定其所属周期 | 高 |
| FR-23 | **轻叩窗扉（双向确认）**的全部前置条件：① 已与该人物开始聊天；② 对方当期意愿为积极且授权有效（含周期一致）；③ 本人当期意愿为积极（"想进一步了解"或"有明确好感"）且已授权当期揭晓；④ 本周期尚未使用确认机会。任一不满足时按钮置灰并显示具体原因 | 高 |
| FR-24 | 确认结果为"有回响"（双方当期均积极）或"本次暂未确认双向心意"；不确认时**对方不收到任何通知**，也不知道用户曾轻叩；结果中不泄露任何私人分数 | 高 |
| FR-25 | 每周期仅一次确认机会；确认机会不因"对方当期不可用"而消耗（不可查询时不消耗机会） | 高 |
| FR-26 | **跨周期失效**：日期推进跨入新周期后，双方授权需要当期重新确认，旧周期授权不延续 | 高 |

### 4.8 屏蔽与举报说明

### 4.11.1 本次补充的需求（不冒称历史实现）

| 编号 | 需求 | 优先级 / 状态 |
|---|---|---|
| FR-36 | 用户可下载状态备份；正常数据导出 UTF-8 JSON 封套，见 §11.5。损坏数据只能导出原始字符串用于诊断，不自动修复；导出失败不得清除原存储。导入恢复本版不提供。 | 中；拟新增，历史源码未实现 |
| FR-37 | 同源多标签页的全部状态修改必须串行执行：使用浏览器 Web Locks 获取同一状态键的写锁，锁内重新读取最新状态、执行动作并校验，再写回；其他标签页收到 storage 事件后重新读取，保留草稿而不覆盖服务端/存储状态。无 Web Locks 支持时禁止状态修改并提示升级浏览器，避免声称可安全并发。 | 中；拟新增，历史源码未实现 |

FR-36 来源是存储损坏后的备份悬空引用；FR-37 来源是可预见的 localStorage 多标签覆盖风险。二者是需求新增，不更改 FR-01～FR-35 编号。FR-37 以同源 Web Locks 能力为环境前提，锁只覆盖同步读写，不得跨 AI 网络请求持锁；模型返回时重新取得锁，按最新 pending 判定是否仍可应用。

### 4.13 页面清单（人机界面）

移动端单列 + 电脑端侧栏布局共用同一套页面：遇见（首页）、纸条（递出的/收到的页签）、聊天页（含心笺/资料入口）、我的（含回望、轻叩窗扉、重置）、AI 连接设置、演示控制面板、人物资料弹层、举报说明弹层。

### 4.14 优先级与使用频率的对应

高优先级功能覆盖主循环的每次使用（浏览→递纸条→回应→聊天→回顾→确认，每个 S1–S5 场景均依赖 FR-01/04/11/12/21–24 等高优先级项）与安全底线（FR-15/20/27）；中优先级为完整性功能（资料查看、收件暂存归档、演示面板）；低优先级仅测试与便利用途（时间推进、草稿），与使用频率由高到低一致。

## 5. 非功能需求

| 编号 | 类别 | 需求（含可获取的指标） | 优先级 |
|---|---|---|---|
| NFR-01 | 性能 | AI 上游调用超时上限 35 秒，超时返回"模型服务响应超时"并允许重试 | 高 |
| NFR-02 | 性能 | 服务端同时处理的 AI 请求最多 4 个，超出返回 429 BUSY（"已有多个请求进行中"） | 中 |
| NFR-03 | 性能 | 单个请求体上限 64KB，超出返回 413；发送给模型的对话上下文最多 20 条、单条 3000 字 | 中 |
| NFR-04 | 安全 | API 密钥仅存在于本地服务进程，**不进入前端代码、localStorage 与日志**；`/api/status` 只返回是否已配置与模型名，不返回密钥 | 高 |

## 6. 业务规则汇总（含与时间相关的功能）

1. **日额度**：每本地自然日 2 次新人物投递，不累积（时间相关：自然日边界）。
2. **七天周期**：自 Demo 初始化起算，每 7 天一个周期（时间相关：周期边界）。
3. **周期内唯一确认**：每周期"轻叩窗扉"仅 1 次（时间相关：周期范围）。
4. **授权周期绑定**：意愿与授权记录所属周期，跨周期自动失效（时间相关：周期比对）。
5. **待回复锁**：同一人物同时最多一个待回复任务，完成前禁止新消息。
6. **不可用不扣额**：被屏蔽、未授权、周期不一致等不可查询情形不消耗确认机会。
7. **私人数据隔离**：心笺分数/备注、查询记录、授权状态仅存本地，永不出机（不发给模型）。

---

### 6.1 日额度的最小敏感性分析

1 次/日使只有一次试探机会，失败或兴趣不符后要等次日；3 次/日允许一天接触全部三位初始人物，降低分批选择的约束；2 次/日作为两者之间的折中，兼顾选择空间与防滥发。此为场景推演而非用户研究结论，不证明 2 优于 1 或 3；后续可以相同 S1 脚本比较完成率、放弃率与压力自评，再决定是否调整。七天周期同样是设计决策，不能用单元测试证明其体验最优。

安全、隐私和核心状态可靠性类 NFR 统一设高优先级；一般性能容量及运维便利性按对主循环的阻断程度设中优先级，不能仅因使用频率低而降低密钥或隐私保护要求。

## 11. 输入/输出数据格式定义（数据字典）

本节集中定义系统的两类输入/输出：浏览器 localStorage 状态对象、本地 HTTP 接口的请求/响应。字段定义均以随包 `证据/core.mjs`（`validState`）与 `证据/server.mjs` 为准。

### 11.1 localStorage 状态对象（key 内应用唯一状态，JSON 序列化存储）

本表区分输入规则与结构校验：字数上限由编辑/业务动作校验；validState 检查版本、结构、角色、分数与部分关联，并非逐字段重查所有字符串长度。历史界面读取失败会显示错误并阻止继续交互，不代表所有非法长字符串都可由 validState 检出；完整读写约束仍须按 NFR-11 验收。

| 字段 | 类型 | 取值范围/约束 | 说明 |
|---|---|---|---|
| `version` | 整数 | 恒为 `1` | 状态结构版本 |
| `started` | 数值 | 有限数（初始化时刻毫秒时间戳） | 七天周期起点（FR-21） |
| `offsetDays` | 整数 | 0–3650 | 演示时间推进天数（FR-34） |
| `profile` | 对象 | `{name: string≤20, habit: string≤100, topic: string≤100, allowNotes: boolean}` | 演示身份（FR-03） |
| `notes[]` | 数组 | 每项 `{id: string, personId: 'xia'\|'yu'\|'ning', direction: 'in'\|'out', text: string（out 向 ≤100）, topic: string, status: 'pending'\|'saved'\|'accepted'\|'declined', at: 有限数, day?: '年-月-日'（out 向），demo?: true（预设来信）}` | 纸条记录（FR-04~07/17/18） |
| `messages` | 对象 | 键为人物 id，值为 `[{id: string, role: 'user'\|'assistant', content: string（user ≤500，assistant ≤3000）, at: 有限数}]` | 对话记录（FR-12/13） |
| `pending` | 对象 | 键为人物 id，值为 `{kind: 'chat'}` 或 `{kind: 'note', noteId: 引用存在且 status='pending' 的纸条}` | 待回复任务（FR-13） |
| `blocked[]` | 数组 | 元素为有效人物 id | 屏蔽列表（FR-27） |
| `feelings` | 对象 | 键为人物 id，值为 `[{score: 0–100 整数, memo: string≤200, at: 有限数}]` | 心笺（FR-19/20） |
| `reviews` | 对象 | 键为人物 id，值为 `{intent: 'exploring'\|'closer'\|'affection'\|'stop', authorized: boolean, cycle: 整数≥0, at: 有限数}` | 本人当期意愿（FR-22） |
| `confirmations[]` | 数组 | 每项 `{id: string, personId: 有效 id, cycle: 整数≥0, mutual: boolean, at: 有限数}` | 轻叩窗扉结果（FR-24） |
| `scenarios` | 对象 | 键为人物 id，值结构同 `reviews` | 演示面板控制的"对方当期状态"（FR-31） |
| `seq` | 整数 | 单调递增 | 本地 id 生成器 |

### 11.2 本地 HTTP 接口

通用约束（所有请求）：Host 必须为 `127.0.0.1:{port}` 或 `localhost:{port}`；POST 须带 `Content-Type: application/json`、同源 Origin、非跨站 `Sec-Fetch-Site`；请求体 ≤64KB。成功响应均为 200 + JSON；错误响应统一为 `{"error": "<中文说明>", "code": "<错误码>"}`（见 11.3）。

| 接口 | 方法 | 请求体 | 成功响应 |
|---|---|---|---|
| `/api/status` | GET | — | `{app:'heart-window-demo', configured: boolean, model: string（未配置为 ''，**不含密钥**）, version:'1.0.0'}` |
| `/`、`/index.html`、`/app.mjs`、`/core.mjs`、`/style.css` | GET | — | 静态文件（白名单，其余路径 404） |
| `/api/check` | POST | `{}` | `{ok: true}`（真实调用一次模型） |
| `/api/suggestions` | POST | `{personId, messages?: [{role:'user'\|'assistant', content: string≤3000}]（≤20 条）, profile?: {name≤30, habit≤150, topic≤150}, context?: string≤200, intent?: string≤30, draft?: string≤500}` | `{suggestions: [{label: string≤12, text: string≤100}]（恰好 3 条）}` |
| `/api/reply` | POST | 同 `/api/suggestions` | `{text: string≤3000}`（AI 人物回应） |

说明：HTTP 中 profile 的 30/150/150 是历史服务端模型请求的接收上限；本地身份编辑更严格，按 FR-03 的 20/100/100。不得将较宽的传输上限误写成界面编辑长度。

### 11.3 错误码表

| HTTP | code | 触发条件 |
|---|---|---|
| 400 | `INVALID_INPUT` | 输入格式/长度不正确、请求体非 JSON、请求体超长（413 亦归此 code） |
| 403 | `FORBIDDEN` | 非本机 Host、跨站 Origin、跨站 Sec-Fetch-Site、非 JSON Content-Type |
| 404 | `NOT_FOUND` | 页面或接口不存在（含白名单外文件，如 `/.env`、`/server.mjs`） |
| 429 | `BUSY` | 本地并发 AI 请求 ≥4（NFR-02） |
| 502 | `TIMEOUT` / `NETWORK` / `AUTH` / `RATE_LIMIT` / `UPSTREAM` / `FORMAT` | 上游超时 35s / 无法连接 / 鉴权拒绝（401、403）/ 限流（429）/ 其他上游错误 / 返回不可解析或不符合格式 |
| 503 | `NOT_CONFIGURED` | `.env` 未配置有效 AI 即调用 AI 接口 |
| 500 | `INTERNAL` | 本地服务内部错误（兜底，正常使用不应出现） |

### 11.4 AI 上游调用格式（约束 C4）

服务端以 `POST {AI_BASE_URL}/chat/completions` 调用，头 `Authorization: Bearer {key}`，体 `{model, messages: [{role, content}...], stream: false}`；要求响应 `choices[0].message.content` 为非空字符串（≤12000 字符，超出或为空按 FORMAT 处理）。`AI_BASE_URL` 必须为 HTTPS 或 loopback HTTP，不含用户信息、查询串与锚点。

### 11.5 备份格式（FR-36，拟新增）

正常下载文件名为 window-backup-YYYYMMDD-HHmmss.json，编码 UTF-8、MIME application/json，封套为：

```json
{"backupVersion":1,"app":"heart-window-demo","exportedAt":"ISO-8601 UTC时间","stateVersion":1,"state":{}}
```

state 必须是 §11.1 定义且通过 validState 的完整快照，示例空对象只是格式占位，不是可用备份；不得包括 .env、AI_API_KEY 或浏览器其他键。backupVersion 表示备份封套版本，stateVersion 必须与 state.version 一致。无导入功能，本版不承诺恢复未知版本；未来增加导入时须另立需求，先验证版本、结构与用户确认再替换当前状态。

损坏数据可另下载 window-backup-raw-时间.txt（UTF-8 text/plain），内容为该应用状态键的原始字符串，保留原值，不把它称为合法 JSON 备份；文件含私人心笺与聊天，不自动上传。历史界面尚无导出按钮，§7 的原值保全步骤目前由开发者工具手动完成。

## 12. 术语表

| 术语 | 含义 |
|---|---|
| 纸条 | 最多 100 字的开场短消息，慢节奏社交的唯一起点 |

| 周期 | 自 Demo 初始化起每 7 天一个的心意确认窗口 |
