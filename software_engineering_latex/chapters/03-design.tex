\section{系统结构}
\subsection{设计依据与实现边界}
“谁能打开你的窗”以低压力相遇、纸条投递和交流为核心；“拾言”是其中的 AI 表达辅助功能。
本章依据当前 \DesignCode{server.mjs}、\DesignCode{lib/*.mjs}、
\DesignCode{public/*.mjs} 的实际实现描述设计，数据库依据
\DesignCode{lib/db.mjs} 的建表、索引与迁移语句，共18张应用表。
“现状”表示源码存在相应处理逻辑，不等同于已经通过生产环境性能或安全认证；
“规划”表示建议的后续方案，不计入已实现功能。

现状为 B/S 结构：浏览器运行原生 HTML、CSS 和 JavaScript ES 模块；
Node.js 单进程通过 \DesignCode{node:http} 提供页面和 API，通过
\DesignCode{node:sqlite} 的 \DesignCode{DatabaseSync} 同步访问 SQLite。
文本及图片模型由服务端调用。项目没有使用 React、Express、ORM、微服务或独立消息队列。
默认监听 \DesignCode{127.0.0.1:3210}，可配置局域网监听和 IP 白名单。
白名单非空时必须启用局域网监听，即使显式关闭局域网也以白名单需要为准。
浏览器到服务端当前仍为 HTTP，不能把局域网演示描述成完善的公网部署。

图\ref{fig:design-architecture}是逻辑职责图，各层并非独立部署进程。

\subsection{HTTP 接口契约}
路径均相对服务根地址。除公开状态、注册和登录外，业务接口需要有效
\DesignCode{hw_session} Cookie。普通 JSON 请求体最多64000字节，媒体上传最多4200000字节。
POST 检查 Content-Type、Origin（存在时）和跨站 Fetch 元信息。
错误返回含 error、code 的 JSON 对象；成功返回业务对象，没有统一 data 包装。
图像读取直接返回二进制，不套 JSON。

\section{关键数据结构定义}
\subsection{字段类型与约束记法}
以下数据字典逐字段对应实际 DDL。T、I、B 分别表示 TEXT、INTEGER、BLOB；
N 表示显式 NOT NULL，PK 表示主键，U 表示唯一，FK 表示声明外键，D 表示默认值。
所有声明 FK 都带 ON DELETE CASCADE，下表不重复写出。
普通 SQLite 表的 TEXT 主键仅声明 PK 不等于显式非空，因此字典单独标明未显式 N；
应用仍写入有效编号。时间通常为 Unix 毫秒，day 则为日期文本。
立绘 updated\_at 同时是单调版本，未必严格等于物理时间。
JSON 为 TEXT，数据库未声明 json\_valid 检查，布尔整数也未统一声明0/1 CHECK。

\section{关键算法设计}
\subsection{标签提取与双向匹配公式}
两段介绍去空白后各10--500字符，不能仅重复同一字符。模型只从24项固定词表提取，
每组1--8项不重复标签，不推断年龄、性别、健康等敏感属性。
保存介绍后清空旧标签并置 pending；模型返回后再次比较两段介绍，未变化才 storeTags 并置 ready。
失败保留介绍供重试，不生成假的成功标签。该字符串比较不是数据库版本式并发控制。

设本人标签集合为 $S_a$，期望集合为 $D_a$，用户 $b$ 同理。
ready 资料保证期望非空。实际 matchScore 计算：
\begin{equation}
r_{a\to b}=\frac{|D_a\cap S_b|}{|D_a|},\qquad
r_{b\to a}=\frac{|D_b\cap S_a|}{|D_b|}.
\end{equation}
\begin{equation}
M(a,b)=\begin{cases}
0,&r_{a\to b}=0\ \text{或}\ r_{b\to a}=0,\\
\operatorname{round}\left[50(r_{a\to b}+r_{b\to a})\right],&\text{其余情况}.
\end{cases}\label{eq:design-match}
\end{equation}
不是 Jaccard 相似度、向量检索或学习排序模型。两个方向满足 $2/3$ 和 $1/2$ 时为58分，
低于60，不入候选；一方向完全不满足时，即使另一方向满分也为0。
分数是标签规则参考，不是爱情成功概率。
recommendations 辅助函数按分数降序、同分按编号排序，默认过滤60分并取10项；
当前 HTTP /api/matches 返回真人收藏，不调用该排行函数。

\subsection{候选筛选与加权抽取}
本人资料需 ready。真人候选排除本人、未就绪者、不允许纸条者、已建会话者及任一方向 pending 纸条者；
虚拟候选取 DRAW\_PEOPLE 中未屏蔽人物。合并后按 kind:id 排除已收藏和未到期冷却，
过滤 $M<60$，输出时去掉 selfTags、desiredTags、persona。
卡片档位为 $M\ge95$ 金色、$85\le M<95$ 紫色、其余合格候选蓝色，档位不是独立概率。

设整数权重 $w_i=M(a,i)$，总票数 $W=\sum_iw_i$。randomInt(W) 等概率取
$0,\ldots,W-1$ 票号，逐项扣减权重，首次变负选中对应人选，故
\begin{equation}
P(i\mid\text{本次候选池})=\frac{w_i}{\sum_jw_j}.\label{eq:design-draw}
\end{equation}
空池先返回 EMPTY\_POOL，不执行零票数抽签。当前需扫描就绪资料与解析标签，
未实现大规模向量索引。抽取响应为 unlimited=true、remaining=null、nextReset=null，day 仅归档。

\subsection{登录与单设备会话流程}
注册在事务中创建 users、状态、初始收藏和会话；匹配资料保存与模型提取在注册函数事务之后，
不是全部注册和模型等待都处于一个事务。密码用独立盐进行 scrypt 派生并恒定时间比较；
账号不存在也进行虚拟摘要派生，减少耗时探测差异。
登录按真实 TCP 对端地址计失败窗口，15分钟内 IP/账号10次或全 IP 30次限流。
成功时事务内将旧会话 active=0 并记录替换设备，清理旧会话后插入新会话，
部分唯一索引保证单活跃。只清 IP/账号失败键，不清全 IP 键，避免用已知账号成功登录不断解除 IP 限制。
浏览器持原令牌、数据库存 SHA-256 摘要，当前有效期30天。
旧设备下一次请求收到 SESSION\_REPLACED，不是主动注销推送。

\subsection{真人纸条与会话建立流程}
投递需已收藏真人、对方允许纸条、无会话和任一方向 pending 纸条；
每日最多两次，按服务器本地零点，不等同于抽取 UTC+8 日期口径。
只有收件人能接受或拒绝仍 pending 的纸条。拒绝置 declined 不建会话；
接受验证100字内回信，排序双方编号，并在一个事务中改状态、建会话、写原纸条和回信两条首轮消息。

\subsection{虚拟回复、对话理解与意愿揭晓}
虚拟发送先验证双向联系、屏蔽和未完成回复，再写本人消息与 pending；
服务端使用最近16条已保存历史及 users 资料调用模型，纸条首轮补入原纸条。
等待模型时不持事务，返回后内部 runAction/finishReply 重读状态；
pending 已清或人物被屏蔽则忽略迟到结果，失败保留重试状态。
当前 pending 无独立请求代号，不能宣称严格的请求级并发防重。

对话理解在调用前核对最新对方消息 messageId，使用数据库或已保存状态历史，返回三种解释和三条可编辑建议。
解释 confidence 为0--100整数、三项和100，是相对参考权重，不是统计概率。
情绪允许 E6、neutral、uncertain，非法/缺失降级 uncertain；只有 E6 且置信度70--100整数才选表情立绘，
对应资源缺失回退 default。情绪不用于心理诊断、授权或意愿揭晓。
服务端在模型等待前核对最新消息；前端返回时再比对 \DesignCode{messageId}，
仅接纳仍对应当前消息的情绪结果，并要求回复风格仍一致才保存建议。
若消息或风格已变且用户仍在查看该会话，前端会补发分析请求；这不是服务端返回后的数据库版本校验。

虚拟时钟和七天周期为
\begin{equation}
t_v=t_{\mathrm{real}}+d\cdot86400000,\qquad
c=\max\left(0,\left\lfloor\frac{t_v-t_{\mathrm{started}}}{7\cdot86400000}\right\rfloor\right).
\end{equation}
揭晓要求未屏蔽、已有双向交流、双方当期授权、本人积极意愿（closer/affection）、账号当期机会未用。
通过后按预设对方意愿是否积极记录 mutual，整个账号周期消耗一次，不是每人物一次。
feelings 只是私人自填分数，不能代替授权；scenarios 是演示对方，不是真人确认。
真人目前只有互动分析双方开关，没有真人周期回望与双向意愿揭晓实现。

\subsection{互动参考分与缓存算法}
真人互动参考分不同于标签匹配分。令回复速度 $R$、持续性 $C$、字数因素 $L$、可选模型分 $A$，
当前综合规则为
\begin{equation}
F=\operatorname{clip}_{[0,100]}\left(
\begin{cases}
\operatorname{round}[0.25(R+C+L+A)],&\text{有有效模型分},\\
\operatorname{round}[0.35R+0.35C+0.30L],&\text{无有效模型分}.
\end{cases}\right).\label{eq:design-favorability}
\end{equation}
回复按时间排序，每次目标用户回复配对此前最近本人消息，结算后清基准，最少0.1分钟。
各间隔分取平均；1分钟内100，之后按1--5、5--15、15--60、60--240、240--720、
720--1440分钟分段线性下降至90、80、65、50、35、20，超过一天继续下降但至少10。
无有效回复默认60，不表示已有真实好感。
持续性按服务器本地日期，从今天或昨天向前统计连续天；消息间隔至多25分钟属于同一片段。
连续天数分和最长片段时长分各占50\%，并不保证每天双方都发过消息。

设目标字数 $n_o$、本人字数 $n_m$，去空白后按 Unicode 码点计数，
当 $n_o+n_m>0$ 时先取 $q=\operatorname{round}[100n_o/(n_o+n_m)]$；总字数为0时直接取默认分。
字数因素为
\begin{equation}
L=\begin{cases}
60,&n_o+n_m=0,\\
\min(100,\operatorname{round}[70+60(q-50)/50]),&q\ge50,\\
\max(15,\operatorname{round}[20+q]),&q<50.
\end{cases}
\end{equation}
高比例分段约在75\%字数占比时即达100，不能照源码注释写成100\%才满分。
因素都是启发式互动指标，受样本量、作息、语言习惯影响，不能证明真实意愿。

读取先核对参与者与双方开关，再比较 last\_message\_id；相同复用整份缓存，
不同则重算规则，可能沿用旧非零模型因素，但不主动调用模型。
因此水位更新不代表模型因素覆盖最新消息，且当前真值判断使旧模型0分不被沿用。
主动分析才以最近20条正文调用模型，失败降级规则。
规划应增加模型自身水位/时间及等待期间授权复查，不把当前缓存写成严格实时分析。

\subsection{生图状态机与执行流程}
生成参考为本人已上传的默认聊天立绘，不是头像，也不是仅文字生成陌生人物。
用户确认发送默认立绘给配置模型并消耗额度，提交 E6 情绪和 requestId。
同账号同编号同情绪复用任务；同编号换情绪返回冲突。任务清理后不提供永久幂等保障。
每账号 running/ready 合计最多一个，全服务 running 上限2，滚动24小时最多12条创建记录，
失败和放弃也计次数。

有效结果写任务预览字节与尺寸并置 \DesignCode{ready}，不覆盖原立绘。

应用前重读默认图摘要和目标情绪版本；一致才开始事务写 user\_sprites，
置 saved 并清 bytes，不一致返回 IMAGE\_STALE 并保持 ready。
摘要检查不等于默认图版本检查：同字节重传仍可通过，检查本身位于写事务之前。
saved 重复 apply 返回当前媒体，不再替换。ready/failed 放弃置 discarded 并清预览；
running 必须等待结束，没有任务取消接口；saved 的 discard 不删除已存立绘。
生成器初始化把遗留 running 置 failed 并清 bytes，不自动重新请求，避免重复扣费。
关闭时中止等待网络请求，关闭期间不再落库，遗留 running 由下次初始化处理。
创建超过7天的非运行任务在查询/创建等调用时触发清理，不是独立定时清理服务。
调度计数和控制器仅在内存，任务和结果在数据库；持久化队列与跨实例抢占仍属规划。

\section{数据管理说明}
\subsection{存储布局与一致性}
默认库为 runtime/app.db，可用 DB\_PATH 改写；openDatabase 创建父目录并启用 WAL 与外键。
测试可使用内存库，本章核查不读取或改写运行账号数据库。
关系数据存表，虚拟状态按账号存 JSON，个人媒体与生成预览存 BLOB；
内置背景和虚拟图片存 public/bg、public/character。
浏览器 localStorage 只保存场景、按账号区分的回复风格等偏好，不是账号、消息或额度的权威来源。
访问采用参数化 prepare/get/all/run，用户文本不拼接为 SQL。

注册、登录、抽取、决定/移除、接受真人纸条、生图确认和启动迁移使用显式事务。
不能概括为所有多表写入都原子化：writeState 更新 users/states 两语句在调用者未包事务时不是整体原子操作，
普通真人消息与会话更新时间同样如此。WAL 改善读写协调，不让同步数据库变成异步，也不替代业务事务。

\subsection{迁移与历史兼容}
启动按 IF NOT EXISTS 建表/索引，然后立即写事务内做兼容处理。
\DesignCode{separate-avatar-sprite-v1} 标记避免重复迁移：旧 user\_portraits 每账号最近图仅在头像缺失时转存 avatar，
保留旧图归档，不自动成为新默认立绘；历史 running/ready 任务置 failed 并清预览。
检测 users 缺好感度开关时补列；旧 draw\_records 若有 user\_id/day 唯一约束则重建，

\subsection{权限、安全与保留策略}
密码摘要、盐、令牌摘要、匹配期望介绍及生图内部摘要不随公开用户对象返回。
背景仅本人，头像/立绘按关系授权，任务/预览/应用均绑定账号；真人会话读取和发送均检查参与者，
不能只凭 UUID 授权。模型输出不执行为代码，建议可编辑且不自动代发，前端有同源 CSP 限制。
Cookie 当前为 HttpOnly、SameSite=Strict、Path=/ 和有效期；HTTP 未加 Secure，
局域网抓包风险仍在，不能写成端到端加密。
普通媒体上传仅校验格式签名和大小，不执行生成 PNG 那样的完整像素处理。

失败窗口由注册/登录触发清理，旧会话在登录时清理，非运行生成任务按创建时间7天触发清理。
消息、纸条、抽取历史与旧图归档没有统一自动保留期限。
FK 级联删除是直接删除父记录时的数据库效果，不表示已有用户注销入口。
数据库静态加密、审计日志、自动备份、恢复演练、图片内容审核均不能描述为已经实现。

\subsection{规划的管理演进}
后续先统一日期口径与数据保留策略，将资料/状态及消息/会话时间的多写入纳入短事务，
对模型等待后资料版本、消息水位及双方开关进行复查，为虚拟回复增加独立请求代号。
公网需 HTTPS/Secure Cookie，并完善真人举报屏蔽、注销、审计和恢复。
规模扩大后考虑异步数据库、持久化生图工作队列、对象存储、跨实例并发与额度控制、
JSON 拆表及索引迁移。SQLite 备份应使用一致性快照或停服后正确处理主库与 WAL，
不能运行中任意只复制主库文件。
这些均为规划，不扩充当前18表，不虚构尚不存在的业务类或部署组件。
