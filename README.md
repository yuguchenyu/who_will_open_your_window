# 谁能打开你的窗 · 本地交互 Demo

手机优先、兼容电脑。此版本有账号系统、真实注册用户之间的 AI 标签推荐、真人纸条与对话，以及三个明确标注的 AI 虚拟人物。真人消息由本人发送，AI 不代替真人回复；「拾言」的判断和建议、虚拟人物回复与匹配标签提取调用服务端配置的模型。没有有效 AI 连接时，真人纸条与对话仍可使用，AI 分析和虚拟人物互动不可用。

## 启动

界面采用米白与鼠尾草绿的水彩设计，包含八种场景、三位默认收藏的演示人物和三位抽卡人物。首次打开新标签页可点击窗扉进入，同一标签页刷新或登录后不重复播放；也可直接进入，系统开启减少动态效果时省略入场动画。场景仍保留雨夜、夜晚、秋日和黄昏变化，可在对话中的“场景”切换。素材与制作提示词见 `docs/watercolor-assets.md`。

已安装 Node.js 24，无需 npm install。双击 `启动Demo.cmd`，或在 PowerShell 运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "E:\谁能打开你的窗\start.ps1"
```

用浏览器打开 **http://127.0.0.1:3210**。必须通过本地服务访问，不能直接双击 HTML。后台服务不随启动终端关闭而退出，重复启动不会创建重复实例。

在 macOS / Linux 上无需 PowerShell，直接运行 `node server.mjs`（等价于 `npm start`）即可，前台运行，Ctrl+C 停止。

## 账号

第一次打开会进入登录页。注册一个账号即可开始，用户名 3–20 位字母、数字或下划线，密码至少 8 位。账号和全部互动数据都存在服务端的 SQLite 里（默认 `runtime/app.db`），换设备登录同一账号能看到自己的记录。

注册时填写两段 10–500 字的介绍：自我介绍，以及希望遇见怎样的人。确认展示和 AI 分析后，服务端调用兼容 Chat Completions 的模型，从固定词表中分别提取本人标签和期望标签。双方各自的期望标签都能匹配对方本人标签时，计算双向契合度；达到 60% 才进入“遇见”的抽卡池。真人与新增的林澈、陈序、唐梨三位 AI 虚拟人物混合抽取，概率与契合度成正比。结果展示姓名、自我介绍、匹配标签和参考契合度，不展示真人对方的择偶描述。旧账号可在“我的匹配资料”补填。AI 未配置或暂时失败时会保留介绍，状态为待提取，可以稍后重试。抽中后点击“喜欢”加入收藏，才能给新匹配的对象递纸条；真人收件人回信后，双方开启真人对话。

**一个账号同时只能在一台设备上登录。** 在第二台设备登录会顶掉第一台 —— 原设备下一次点击时会提示"你的账号已在另一台设备登录"并退回登录页。

## 已知限制

这是一个课程作业，以下都**没有**做，不要在真实环境里这样用：

- **令牌在局域网内是明文传输的。** 服务跑在 HTTP 上，所以会话 cookie 没有加 `Secure` 标记 —— 加了浏览器就不会回传，登录会直接失效。上线必须换 HTTPS 并把 `Secure` 加回去。
- **没有找回密码。** 忘记密码只能直接改数据库里的 `users` 表。
- **会话固定 30 天过期**，不滑动续期。
- **被顶掉的设备不会立刻收到通知**，通常在下一次操作或页面自动同步时发现。
- **真人与 AI 演示人物分开标记**。真人消息不会由模型冒充对方发送；拾言判断只是参考推测，不能确认对方真实想法。
- 没有邮箱验证、验证码、设备指纹。

## 让同一局域网的其他设备访问

默认**只监听 127.0.0.1**，其他设备连不上。要临时放开，在 `.env` 里加一行后重启：

```dotenv
ALLOW_LAN=1
```

服务会改为监听 `0.0.0.0`，启动日志会打印形如 `LAN: http://10.22.37.8:3210` 的地址，在其他设备浏览器打开该地址即可。放开的只是本机自己的网卡地址，陌生 Host 和端口不符的请求仍返回 403。

### 只放行指定设备

比开整个网段更稳的做法是白名单，在 `.env` 里写：

```dotenv
ALLOW_IPS=10.22.37.9,10.22.37.14
```

填了 `ALLOW_IPS` **就自动开启局域网监听**，不用再设 `ALLOW_LAN=1`。校验的是 TCP 对端真实地址（`req.socket.remoteAddress`），**不信任 `X-Forwarded-For`**——那个头谁都能伪造。本机 `127.0.0.1` 始终放行，不会把自己锁在外面。被拒的设备会收到写明自己地址的 403，方便排查：

```json
{"error":"该设备（10.22.37.9）不在 ALLOW_IPS 白名单中。","code":"FORBIDDEN"}
```

两点注意：只支持单个 IP，不支持 `10.22.37.0/24` 这种网段写法；手机等 DHCP 设备的地址会变，变了就连不上，需要重新填。地址写错（如 `10.0.0.999`）时服务会直接启动失败并指出是哪一项，不会静默失效。

三点务必先知道：

1. **`/api/*` 现在需要登录。** 登录门槛之外还保留了原有的 Host、Origin、`Sec-Fetch-Site` 与 `ALLOW_IPS` 检查。但会话令牌在局域网内是明文传输的（见「已知限制」），只在你信任的网络里开，用完把 `ALLOW_LAN` 改回 0 并重启。
2. **数据在服务端，按账号隔离。** 同一账号换设备登录能看到自己的记录；不同账号互相看不到对方的数据。
3. **有些网络存在 AP 客户端隔离**（同一 WiFi 下设备互相不通）。若改完仍连不上，先用另一台设备 `ping` 本机地址确认，再排查服务。

## 服务端 AI 配置（仅管理员）

项目已准备不含有效密钥的 `.env`。在本地编辑以下项，不要把密钥发给别人或提交到版本库；如果文件不存在，将 `.env.example` 复制为 `.env`：

```dotenv
AI_BASE_URL=https://你的服务商地址/v1
AI_MODEL=模型名称
AI_API_KEY=你的密钥
PORT=3210
```

服务需兼容非流式 `POST /chat/completions`，以 `Authorization: Bearer ...` 鉴权，并返回 `choices[0].message.content` 字符串。AI_BASE_URL 是该路径前的地址，不要重复写 `/chat/completions`。支持 HTTPS 服务，也支持 loopback 上的 HTTP 模型服务。只支持这个兼容协议，不保证所有服务商的专有协议可用。

修改配置后重启服务。网页会自动使用服务端配置，不提供用户修改或查看接口地址、模型和密钥的入口。每次标签提取、建议或人物回应都会调用真实模型，可能产生费用。

密钥不进入前端、本地存储和日志。对话生成仅发送人物设定、用户主动填写的简要资料、当前草稿和最近最多 16 条对话。私人分数、心笺备注、查询记录和授权不发送给模型。对话会离开本机发送到你配置的服务商，请按其政策选择输入内容。

## 体验路线

1. 在「遇见」查看人物和「留一扇窗」的话题，递一张最多 100 字的纸条。
2. 写纸条时可以自己输入，也可选表达方向后调用「拾言」。点击建议只会进入编辑框。
3. 在「递出的」里点击明确标记的 AI 演示按钮，让虚拟人物回应。成功后开启正常对话。
   每次收到虚拟人物的新回复后，「对话」页会自动分析最近的交流。场景中出现三个 AI 回复选项和一个“自己输入”选项；点击 AI 选项只会填入底部输入框，可修改后发送。三种可能的意思及相对参考权重以小字显示在底部对话框。文字推测不能确认对方真实想法；需要时直接询问对方。
   在「我的 → 设置场景与形象」可上传自己的背景（最多 3 MB）和虚拟形象（最多 2 MB），支持 PNG、JPEG、WebP。背景只用于自己的对话场景；形象会展示在匹配资料及真人对话中。没有上传形象的对象显示问号人。图片保存在服务端账号下，不发送给 AI；删除后可恢复默认显示。背景在页面刷新后会按服务端版本重新加载，失败时可点击“重载背景”。
   真人流程：在「遇见」给推荐用户递纸条；对方在「纸条」回信后，双方可在「对话」继续聊天。真人消息会在页面可见时约每 6 秒同步一次，并显示发送时间。每天最多向两位真人递纸条，同一对用户在纸条待回应时不能重复递送。拾言分析进行中，你仍可自行输入和发送。
4. 通过「我的」或聊天页的「心笺」记录好感；通过「回望」确认当周期意愿及授权。
5. 在右上角 Demo 面板把对应虚拟人物设为当周期「想进一步了解」且已授权，回到「我的」轻叩窗扉，可看到双向结果。
6. 另一条路线：在 Demo 面板选择没有互动的人物，注入一张**预设演示来信**，体验回复、暂存或归档。来信明确标注，不冒充 AI 生成。

虚拟人物演示每天最多向两名新人物递纸条，次数不累积；同一人回应前不可再递。真人纸条另有每天两张的限制。七天周期从该账号的演示状态初始化时起计算，周期内仅一次心意确认。演示纸条的日额度以本地自然日计算。推进日期跨周期后，双方授权需要重新确认。未授权或没有有效状态的对象不可查询，不消耗机会。对方当期是否积极，仅在演示面板可人为设置；AI 不判断真实好感。

收件暂存、归档和未确认结果仅作为本地私密状态展示。回复表示愿意交流，不表示恋爱好感。屏蔽立即停止互动并撤销授权，Demo 中通过重置才能恢复。没有真实审核团队，举报入口只解释边界并提供屏蔽。

## 数据与演示边界

账号与全部互动数据存于服务端的 SQLite 文件（默认 `runtime/app.db`），按账号隔离：换设备登录同一账号能看到自己的记录，不同账号互相看不到。这个文件里是所有人的账号和聊天记录，不要提交、不要外发。密码用 scrypt 加盐哈希后保存，会话令牌只存哈希值，原文只在 cookie 里。私人状态是产品演示语义，不是安全的多用户权限体系；能读到数据库文件的人可以看到全部记录。此项目不适合直接作为真实交友服务上线。

AI 失败后保留已发送消息和待回复状态，重试不会重复发送你的消息。写了一半的草稿会在被迫退出登录（被别的设备顶掉、会话过期）前存一份，重新登录后自动放回输入框。重置有二次确认，只清除当前账号的纸条、聊天、心笺、授权与模拟时间，账号本身保留，也不修改 .env。

## 相遇抽卡与收藏

测试阶段不限制每日抽卡次数，可连续抽取。抽卡动画约 3 秒，可跳过；金色为 95–100%，紫色为 85–94%，蓝色为 60–84%，颜色表示标签契合度，不是关系成功率。动画中刷新或关闭页面后，结果仍会保留，需先决定喜欢或跳过才能再次抽取。

收藏最多 5 位，满员后需先移除一位才能抽取。跳过或移除的对象 30 天内不会再进入抽卡池；移除收藏不会删除已有纸条和聊天。暂无合格候选人或资料未完成时无法抽取。抽卡记录和收藏保存在账号数据库中。

原有小夏、阿屿、小宁默认放入“留在窗边的人”，占用 5 个收藏位中的 3 个，不消耗抽卡次数；可直接递纸条或继续聊天。初始人物显示“初始相遇”，不虚构契合度。移除后不会因刷新或重启重新加入；旧账号已有收藏会保留，只用空余位置补入初始人物。三位新人物只通过抽卡解锁；林澈 17 岁（户外社团成员）、陈序 20 岁（音乐专业学生）、唐梨 24 岁（甜点师），均为明确标注的女性 AI 虚拟人物。新角色的标签采用固定人设，不需要每次抽取时调用 AI；聊天仍使用服务端配置的模型。

## 查看状态、停止与恢复

```powershell
# 单次只读检查；加 -Watch 持续查看，Ctrl+C 仅退出监控
powershell -NoProfile -ExecutionPolicy Bypass -File "E:\谁能打开你的窗\monitor.ps1"
# 停止指定 Demo 服务
powershell -NoProfile -ExecutionPolicy Bypass -File "E:\谁能打开你的窗\stop.ps1"
# 恢复：再次运行 start.ps1，浏览器中的记录仍保留
```

日志为 `runtime/server.log`、`runtime/server-error.log`，进程状态及已知退出码为 `runtime/service.json`。进程意外退出后，监控以实际 PID 和健康接口为准；未知退出码不会被伪造。服务仅监听本机 127.0.0.1。
